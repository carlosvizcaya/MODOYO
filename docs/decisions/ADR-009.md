# ADR-009: Integración de IA Generativa para Personalización de Ejercicios

**Estado:** Propuesto (Fase 3 — Roadmap Futuro)
**Fecha:** 2026-08-02
**Autores:** Equipo MODO YO
**User Stories relacionadas:** (futuras) — deriva del Roadmap §19 del blueprint

## Contexto y Problema
El roadmap (Fase 3) contempla **IA generativa** para crear ejercicios personalizados basados en las metas del usuario. Dado que se trata de datos de menores y contenido privado, la elección del proveedor y la arquitectura de privacidad son críticas. Esta decisión se documenta como **propuesta** para evaluarse cuando se aborde la Fase 3.

## Alternativas Consideradas
1. **OpenAI API directa** — Pros: calidad de generación, ecosistema. Contras: envío de datos a terceros, coste, latencia, consideraciones de privacidad de menores.
2. **Abacus.AI (mencionado en el blueprint §7)** — Pros: plataforma ya usada como orquestador del proyecto, personalización. Contras: por evaluar en términos de coste/latencia para uso en producción móvil.
3. **Modelo alojado / on-device** — Pros: máxima privacidad. Contras: complejidad y coste de infraestructura elevados para el alcance actual.

## Decisión
**Pendiente.** Se difiere a la Fase 3. Cuando se aborde, la decisión debe priorizar: (1) no exponer contenido privado del adolescente sin anonimización, (2) coste/latencia aceptables para móvil, (3) alineación con la privacidad radical (ADR-002).

## Consecuencias
- **Positivas (esperadas):** Ejercicios adaptados a las metas del usuario; mayor personalización.
- **Negativas/Riesgos:** Privacidad de datos de menores; coste variable; latencia.
- **Mitigaciones (a definir):** Anonimización/agregación antes de enviar datos; capa de abstracción de proveedor de IA para poder cambiar de motor; evaluación de coste antes de producción.

## Notas Técnicas
- Blueprint §7 sugiere Abacus.AI para personalización (fase futura); §19 lo ubica en Fase 3.
- Diseñar una interfaz de abstracción (`AIProvider`) para no acoplar el código a un proveedor concreto.
