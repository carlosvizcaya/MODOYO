# ADR-004: Zustand como Gestor de Estado

**Estado:** Aceptado
**Fecha:** 2026-08-02
**Autores:** Equipo MODO YO
**User Stories relacionadas:** US-003, US-009, US-012

## Contexto y Problema
La app necesita gestionar estado de progreso (XP, niveles, rachas, metas) con soporte **offline-first**: guardar localmente y sincronizar con Supabase al reconectar (US-012). Se busca simplicidad y bajo peso para mantener el rendimiento (<2s de carga).

## Alternativas Consideradas
1. **Redux (+ Redux Toolkit)** — Pros: ecosistema maduro, DevTools. Contras: boilerplate, sobredimensionado para el alcance del MVP.
2. **Context API + useReducer** — Pros: nativo de React. Contras: rendimiento pobre en estados grandes, sin persistencia integrada.
3. **Zustand (elegida)** — Pros: API mínima, bundle ligero, middleware de persistencia (`persist`), fácil de razonar. Contras: ecosistema menor que Redux.

## Decisión
Usar **Zustand** con `persist` middleware para almacenamiento local del progreso diario y sincronización con Supabase al detectar conexión.

## Consecuencias
- **Positivas:** Bundle ligero, menos boilerplate, persistencia offline sencilla, buen rendimiento.
- **Negativas/Riesgos:** Menos convenciones estructuradas que Redux; el equipo debe acordar patrones de stores.
- **Mitigaciones:** Definir convención de stores por dominio en `/src/store`; documentar patrón de sincronización (ver ADR-006).

## Notas Técnicas
- Ubicación: `/src/store`.
- Persisted storage con estrategia offline-first.
