# ADR-001: Uso de Supabase como Backend-as-a-Service

**Estado:** Aceptado
**Fecha:** 2026-08-02
**Autores:** Equipo MODO YO
**User Stories relacionadas:** US-006, US-007, US-005, US-013

## Contexto y Problema
MODO YO necesita autenticación (dual: tutor y adolescente), base de datos relacional, almacenamiento de assets y funciones de servidor (edge functions). Se requiere velocidad de desarrollo para el MVP sin montar y mantener infraestructura de backend propia.

## Alternativas Consideradas
1. **Firebase (Google)** — Pros: maduro, buen tier gratuito, tiempo real. Contras: base NoSQL (Firestore) poco natural para el esquema relacional del blueprint, vendor lock-in fuerte.
2. **Supabase (elegida)** — Pros: PostgreSQL nativo (relacional, encaja con el `Data Schema` del blueprint), Auth integrado, Storage, Edge Functions, Row Level Security (RLS) para privacidad, open-source. Contras: dependencia de un proveedor gestionado, RLS con curva de aprendizaje.
3. **Backend custom (NestJS + PostgreSQL en AWS)** — Pros: control total. Contras: mucho más tiempo de desarrollo y mantenimiento, sobredimensionado para el MVP.

## Decisión
Se adopta **Supabase** como backend principal (Auth + PostgreSQL + Storage + Edge Functions). PostgreSQL encaja directamente con el esquema de datos definido en el blueprint (`users`, `executive_functions_scores`, `daily_logs`, `user_goals`), y RLS permite implementar la barrera de privacidad tutor/adolescente (ver ADR-002).

## Consecuencias
- **Positivas:** Desarrollo rápido del MVP, base relacional nativa, RLS para privacidad, un solo proveedor para auth/db/storage.
- **Negativas/Riesgos:** Dependencia de un proveedor gestionado; posible necesidad de migración si se escala más allá de sus límites.
- **Mitigaciones:** Al ser PostgreSQL estándar, la migración a un backend propio es viable; mantener la lógica de negocio desacoplada del SDK de Supabase.

## Notas Técnicas
- Módulos: Supabase Auth, Database (PostgreSQL), Storage, Edge Functions.
- Endpoints del blueprint implementados como Edge Functions: `POST /auth/register_tutor`, `POST /user/onboarding`, `GET /exercises/daily`, `POST /progress/complete`.
