# ADR-008: NativeWind (Tailwind CSS para RN) como Sistema de Estilos

**Estado:** Aceptado
**Fecha:** 2026-08-02
**Autores:** Equipo MODO YO
**User Stories relacionadas:** US-008, US-010 (look & feel general)

## Contexto y Problema
La UI debe tener un look "videojuego de productividad" (energético, moderno, oscuro-dinámico) y desarrollarse rápido con componentes atomizados y consistentes. Se necesita un sistema de estilos productivo y coherente.

## Alternativas Consideradas
1. **StyleSheet nativo de React Native** — Pros: sin dependencias. Contras: verboso, menos consistente, sin sistema de design tokens.
2. **styled-components** — Pros: CSS-in-JS. Contras: overhead en runtime, menos alineado con utilidades.
3. **NativeWind (elegida)** — Pros: sintaxis Tailwind (utilidades), design tokens consistentes, familiaridad del ecosistema web, velocidad de UI. Contras: dependencia adicional, requiere configuración con Expo.

## Decisión
Adoptar **NativeWind** (Tailwind CSS para React Native) como sistema de estilos, aprovechando utilidades y tokens de diseño para mantener consistencia visual.

## Consecuencias
- **Positivas:** Desarrollo de UI rápido y consistente; design tokens centralizados; baja curva para quien conoce Tailwind.
- **Negativas/Riesgos:** Dependencia adicional; configuración con el pipeline de Expo/Metro.
- **Mitigaciones:** Definir paleta y tokens en la config de Tailwind; documentar convenciones en `/src/components`.

## Notas Técnicas
- Componentes atomizados en `/src/components`.
- Tema oscuro-dinámico definido como preset de Tailwind.
