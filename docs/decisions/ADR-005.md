# ADR-005: React Native + Expo como Framework Multiplataforma

**Estado:** Aceptado
**Fecha:** 2026-08-02
**Autores:** Equipo MODO YO
**User Stories relacionadas:** US-008, US-010, US-011

## Contexto y Problema
MODO YO es una app **mobile-first** para adolescentes que debe funcionar en iOS y Android con un único código base, ofrecer notificaciones push, animaciones ricas (evolución de avatar, celebraciones) y permitir iteración rápida durante el MVP.

## Alternativas Consideradas
1. **React Native CLI (bare)** — Pros: acceso total a módulos nativos. Contras: configuración y mantenimiento nativo complejos, despliegue más lento.
2. **Flutter** — Pros: rendimiento, UI consistente. Contras: Dart (menor familiaridad del equipo), aleja del ecosistema React/Tailwind del blueprint.
3. **React Native + Expo (Managed Workflow) (elegida)** — Pros: desarrollo rápido, EAS Build para despliegue, Expo Notifications, OTA updates, ecosistema JS/TS. Contras: limitaciones con módulos nativos muy custom.

## Decisión
Adoptar **React Native + Expo (Managed Workflow)**, con **EAS Build** para despliegue a App Store / Google Play y **Expo Notifications** para push (US-011).

## Consecuencias
- **Positivas:** Iteración rápida, un solo código base iOS/Android, notificaciones y OTA integradas, encaja con NativeWind (ADR-008) y Zustand (ADR-004).
- **Negativas/Riesgos:** Limitaciones si se necesita un módulo nativo no soportado por Expo.
- **Mitigaciones:** Expo permite `development builds` / `config plugins` y, en último caso, `prebuild` para acceder a código nativo sin abandonar el flujo.

## Notas Técnicas
- Despliegue: Expo EAS Build; CI/CD con GitHub Actions a canales de test.
- Animaciones: LottieFiles para celebraciones de éxito.
